### Accounting — Rust numerics

- **Connect-the-Dots probability formula** (`connect_the_dots.rs:128-138`) re-derived from the hockey-stick recurrence: with `D_i = delta(eps_i)` on a uniform grid of gap d, `p_i = [e^d(D_{i-1}−D_i) − (D_i−D_{i+1})]/(e^d−1)` for interior i, `p_0 = (1−D_0) − (D_0−D_1)/(e^d−1)`, `p_{n-1} = (D_{n-2}−D_{n-1})/(1−e^{−d})`. All three code branches match exactly, including the sign conventions on `delta_diffs`, `expm1_d`, `expm1_neg_d`.
- **Grid endpoint rounding is conservative:** `rounded_epsilon_upper` uses ceil, `rounded_epsilon_lower` uses floor (`:58-59, 203-204, 248-249`), and all mass above the upper endpoint is assigned to `infinity_mass` as `delta(eps_upper)` (`:147`), contributing fully to δ.
- **Chernoff truncation** (`numerics/truncation.rs:124-158) is sound and rounds the safe way: the MGF bound `P(S>=k) <= exp(n·log_mgf − order·k)` is inverted correctly for both tails, the upper bound uses `.ceil()` and the lower `.floor()`, taking min over upper candidates and max over lower candidates preserves validity (each individual order gives a valid bound), and a zero budget short-circuits to the full range. Float-to-int casts saturate in the safe direction.
- **The circular-FFT aliasing fallback is genuinely bounded by the tail budget** (contrary to initial suspicion): since the extraction window `[lower, upper]` has length ≤ `fft_len`, its indices occupy distinct residue classes, so each true convolution index outside the window aliases into at most one read position; total spurious mass is ≤ right_budget + left_budget, and the right budget is separately added to `infinity_mass` (`dense.rs:338`). On the alias-free branch the `% fft_len` at `fft.rs:256` is provably a no-op because `upper_bound <= full_result_len − 1 <= fft_len − 1`.
- **`Pmf::coarsen`'s pessimistic index shift** (`dense.rs:416-421`) strictly over-estimates: group j covers original indices whose maximum loss is `(aligned_lower + j·f + f − 1)·delta` while the assigned coarse loss is `(aligned_lower + j·f + f)·delta` — exactly one delta higher. Mass is conserved and the padding/floor_div alignment handles negative lower indices correctly.
- **`pmf_epsilon`'s `mass_lower == 0.0` early return** (`metrics.rs:171-173`) is safe despite differing from dp_accounting (which returns infinity there): it can only fire on the first iteration where `mass_upper` crosses `target_delta`, and at that point the pre-update `mass_upper` — which upper-bounds δ at the returned loss — was still below `target_delta`.
- **Infinity-mass composition is numerically correct and stable:** the union formula `1−(1−p)^k` is evaluated as `−(count · (−p).ln_1p()).exp_m1()` (`dense.rs:328-332, 344-348`), avoiding cancellation at p ~ 1e-15, and the pairwise `P(A)+P(B)−P(A)P(B)` in compose (`:245-247`) is right for independent events.
- **No `unsafe` blocks anywhere in the crate**; the single `unreachable!()` (`parallel_poisson.rs:214`) is guarded by an earlier early-return on the same match arm. No integer-overflow-prone arithmetic on realistic inputs in the grid/bounds paths.
- **Conservative treatment of secondary truncations:** truncated-Poisson mixes component deltas by the truncation probability (`truncated_poisson.rs:162`) using `max(ADD, REMOVE)` for component 1; parallel-Poisson assigns δ = 1 to the K-tail it drops (`head_mass·delta_head + tail_mass`, `parallel_poisson.rs:88`). Both round toward larger δ.
- **`parallel_poisson_gaussian_pld` correctly models replicated-dataset multi-worker sampling** as a Binomial(m, rate) sensitivity mixture with an explicit K-tail truncation budget added back into δ. The accounting primitive is right; **OPQ-029** is the example script bypassing it.

### Clipping and sensitivity threading

- **Noise σ is always derived from the enforced clip.** `gaussian_noise` computes σ from `ClippedPytree.max_norm` only (`_gaussian.py:306-318`) and takes no clip-norm parameter of its own; `clipped_fun` sets `max_norm = clipping_norm / normalize_by` from the very same `clipping_norm` it passes to `clip_pytree`. There is structurally no second copy to desync. Adaptive clipping threads the *current* threshold into the inner `clipped_grad` (`_adaptive.py:419`), so σ tracks the realised bound step by step; the empty-batch short-circuit attaches the same bound.
- **`normalize_by` cannot become data-dependent:** a factory-time float validated `> 0` (`_clipped_grad.py:55-58`), captured in the closure, never read from a realised batch. Every call site in the library, docs and `DPTrainer` binds it to a constant, so the per-record sensitivity C/normalize_by stays data-independent. This kills the classic "divide by the realized batch size" mistake at the API level.
- **AUTO-S sensitivity is sound and conservative:** `auto_scale_pytree` scales by `R/(‖v‖+γ)` with γ > 0 enforced, so the output norm is `R·‖v‖/(‖v‖+γ) < R` **strictly**, and `max_norm = R/normalize_by` is a fixed, data-independent constant — which is what the docstring claims and what the MF latch requires. NaN/Inf leaves are zeroed before the norm reduction in both `clip_pytree` and `auto_scale_pytree`. The Bu et al. NeurIPS-2023 attribution is correct and the implemented rule is AUTO-S (γ=0.01), not AUTO-V.
- **Per-group noise allocation is privacy-correct:** σ_g = nm·√(C_g·Σ_h C_h) satisfies `Σ_g (C_g/σ_g)² = 1/nm²` **exactly**, so the joint per-group release has the PLD of `gaussian(nm)` for any K and any C_g — matching the docstring's "no composition penalty". `PerGroup.effective = √(ΣC_g²)` is the correct global L2 bound. `noise_multiplier == 0` short-circuits correctly avoid `0 · sqrt(inf)` NaN, and are duplicated in the right places (`per_group_noise_stddev`, `paired_noise_stddevs`, `_clipped_stddev`, `_noise_fn_impl`).
- **Paired first/second-moment allocation math** (`noise_allocation.py:136-232`): with σ_g = nm·√(Δ_g·S) and S = Σ_h(Δ¹_h + Δ²_h), the Mahalanobis budget telescopes to exactly 1/nm², so the joint release has the same PLD as a single sensitivity-1 Gaussian at nm. The bound Δ² = C²/normalize_by is correct (‖g∘g‖₂ ≤ ‖g‖₂² on the L2 ball), and treating the joint constraint set as a product of balls over-estimates the true set — erring toward more privacy. The docs' derived figures check out (√(1+C) → +4.9% at C=0.1, +41% at C=1, matching `clipping.md:411-421`).
- **`per_group_noise_stddev` honestly caveats its optimality claim** ("for equal group dimensions"), unlike `ClippedPytree.noise_stddev_for`'s docstring — the true optimum is σ_i ∝ √(C_i/√d_i).
- **`adaclip_sensitivity` implements Andrew et al.'s *combination* correctly:** z̃ = √(1/z² + K/(4σ_b²)), i.e. 1/z_eff² = 1/z² + K/(2σ_b)². Both `Poisson.pld` and `ParallelPoisson.pld` route `AdaClip.effective_noise_multiplier` (not the raw nm) into the subsampled PLD — the correct direction, charging strictly more than a bare `gaussian(nm)`. The per-group adaptive path draws genuinely independent noise per group via `fold_in(fold_in(key, step), group_index)`, matching the K-query model. (The *centering assumption* behind the `/4` is **OPQ-014**; the composition itself is right.)
- **Microbatching does not break the per-example sensitivity argument:** clipping happens inside the vmapped `per_example_fn` before any reduction, and `_microbatch_accumulate` only sums already-clipped values across chunks. No per-example clip norm ever depends on another example. (The aux-materialisation and dtype defects — **OPQ-022**, **OPQ-043** — are memory and numerics, not sensitivity.)
- **DDP adaptive-clipping resync keeps thresholds identical across ranks:** all ranks enter step t with the same post-sync `_next_clipping_norm`; both the empty-batch and non-empty paths set `_current_clipping_norm` to that value; and `sync_adaptive_clip_state` recomputes the next threshold deterministically from the globally reduced counts using `fold_in(key, step−1)` — the same draw every rank makes locally. No rank can clip at a different C than the `max_norm` metadata advertises.
- **Norm-reduction accumulation dtype** (`pytree.py:305-366`, `clipping/_pytree.py:22-48`): bf16/fp16 always promote to at least fp32, fp64 stays fp64 via `promote_types`, complex leaves accumulate magnitudes in the matching real dtype, non-real compute dtypes are rejected with an explicit `TypeError`, and the per-leaf square-sum uses an explicit `sum(dtype=real_acc_dtype)` so no fp16 intermediate exists. Empty-tree returns a correctly-typed zero. Independently checked: fp32 sum-of-squares of a unit-norm 1e6-dim vector = 1.0000000255.
- **`ClippedPytree`'s arithmetic surface** (`types.py:316-347`) is correctly narrow: `__add__`/`__radd__`/`__sub__`/`__rsub__`/`__pow__`/`__rtruediv__` all raise `TypeError` pointing at `.pytree`; non-Real scalars (including bool) are rejected; division by zero raises; the permitted mul/div/neg scale `max_norm` **and** (on `NoisedPytree`) `noise_stddev` consistently by `abs(factor)`; `clone()`/`detach()`/`to()` use `dataclasses.replace` and preserve both metadata fields.
- **No path lets a never-noised value reach an optimizer:** `_chain.py:142-157` and `_sgd.py:30-35` raise on a bare `ClippedPytree` ("received ClippedPytree updates that have not passed through a noise mechanism"), including per-leg for `SecondMomentNoiseOutput`. Symmetrically `gaussian_noise` rejects `NoisedPytree` input (no double-noising) and rejects raw pytrees (so `max_norm` can never be defaulted).
- **fp16 underflow in the second-moment stream is not a defect:** 13.8% of entries underflow to exactly zero in fp16 for a 1e6-dim unit-norm gradient, but the aggregate sum of squares is still 0.9993, and the DP noise on the squared stream (σ ≈ 3.9e-3 at C=1, n=256, nm=1) is three orders of magnitude larger than the ~1e-6 quantities lost. The sensitivity bound C²/normalize_by is also correct since `‖g²‖₂ = √(Σg_i⁴) ≤ ‖g‖₂²`.

### Sampling

- **Poisson inclusion probability matches the accountant.** `_plain_poisson_step_indices` draws `rng.random(num_examples) < sample_rate` — a genuine per-example independent Bernoulli over the whole dataset each step — and the same q is what `poisson(..., sample_rate=q)` receives. Under DDP the trainer shards first and folds the rank into the sampler key, so each record's marginal inclusion probability stays exactly q. Precision is float64 (numpy PCG64), so the realised probability matches to ~1e-16.
- **The `truncated_batch_size` cap is the mechanism the accountant models:** `_maybe_truncate_indices` does `rng.choice(indices, size=cap, replace=False)` — a uniform without-replacement subsample of the Poisson set — which is the construction `truncated_poisson_gaussian_pld` analyses. Applying it per-shard under DDP is *conservative* relative to the global bound.
- **Min-sep Toeplitz sensitivity** (`_toeplitz.minsep_sensitivity_squared`, Theorem 2 of arXiv:2405.13763) is **exactly** correct — reimplemented in numpy and checked against brute-force maximisation over all start offsets for four (coef, min_sep, k, n) configurations including the boundary case where `min_sep*k < len(vector)` triggers the shifted-subtraction correction; all matched to 1e-9. The in-place `vector[b*k:] = vector[b*k:] − vector[:len−b*k]` is safe because torch materialises the RHS before assignment.
- **`BMinSepSampler` realises min-separation exactly `bands`.** Tracing the cooldown recurrence (decrement-then-set, `:119-125`), an example selected at step t has `_bars_left == 1` when eligibility is computed at t+b−1 and 0 at t+b, so the next possible participation is exactly b steps later — matching `BMinSep.min_sep = strategy.bands`. The warm start uses P(eligible) = 1/(1+(b−1)p), the exact stationary probability of the chain and the exact inverse of `participation_p_from_per_example_rate`. The Binomial-count-then-uniform-subset draw is exactly equivalent to independent Bernoulli(p) inclusion per eligible example.
- **Cyclic-Poisson accounting matches the runtime sampler.** `CyclicPoissonSampler` activates group `i % bands`, so a worst-case example gets exactly `ceil(n_steps/bands)` participation opportunities — precisely the `num_groups` the PLD self-composes. `BandMfStrategy.sensitivity` returning `‖coefs‖` is right because `optimize()` normalises coefficients to unit L2 and because CᵀC for a b-banded lower-triangular Toeplitz is b-banded, so at min_sep = bands the cross terms vanish.
- **Sampler checkpoint/resume is sound across all four samplers:** every `_from_state_dict_*` validates the template dataset length against the snapshot and refuses a mismatch (partition / bin assignment / Markov chain all depend on N), with reasoning about why a mismatch would void the amplification analysis. The two path-dependent samplers (CyclicPoisson, BMinSep) fast-forward by replaying `consumed` discarded `_sample_step` calls through the same generator, so the post-resume stream is identical to an uninterrupted run. `PoissonSampler`'s snapshot additionally replays the extra `rng.choice` draws consumed on truncated steps, landing the numpy generator on a bit-identical continuation.
- **`local_shard` / `_local_shard_bounds`:** argument validation is complete (negative size, world_size < 1, rank out of range) and the last-rank-remainder policy is documented. It does **not** distort the Poisson sampling rate — each record belongs to exactly one shard and is included with probability q — so uneven shards are an ergonomics issue, not an accounting one.

The matched substring "device type for generator" is exactly what ATen emits (`ATen/core/Generator.h:155`), so the fallback fires reliably and the stream stays CPU-generator-derived on CUDA and MPS alike — which λ-CGD's PRNG replay depends on.
- **`BisrStrategy.sensitivity` dominates the (wrongly-built) deployed operator** in every configuration checked — bandwidth ∈ {2,4,8} × normalized ∈ {T,F} × five (n, min_sep, k) configs, ratios 0.69–1.00 — so **OPQ-016** is a utility defect, not a privacy one.

### Optimizers

- **Bias-correction EMA/accumulator rate matching** — each optimizer's φ recursion was checked against the accumulator it is subtracted from and **all five are algebraically correct**: Adam/AdEMAMix/RAdam use `φ_t = β₂φ_{t−1} + (1−β₂)σ²` and divide *both* φ and ν by `(1−β₂^t)` before subtracting; RMSprop applies no `(1−α^t)` divide to either, matching its uncorrected ν; Adagrad accumulates φ cumulatively with no decay, matching its non-decaying `v_acc`; Adafactor drives φ with the same time-varying `β₂_t = 1 − t^c` as the row/col factors, and because the per-element noise bias is a uniform +σ² it propagates cleanly through both the row mean and the column mean; Adadelta's `φ_dx = ρφ_dx + (1−ρ)·coef²σ²` is the correct variance propagated through the linear map `Δx = −coef·g̃`, with `coef` computed before the noise enters.
- **Weight decay × noise interaction** — both chain layouts are sound. In the L2 form, `add_decayed_weights` runs before the moment scaler so ν accumulates `(g̃ + wd·p)²`; since `wd·p` is a deterministic function of the parameters it shifts the mean and contributes nothing to the variance, so subtracting exactly σ² remains correct. In the decoupled form the moment scaler never sees the decay term. No path lets the weight-decay magnitude leak into or distort the φ-EMA.
- **No optimizer state requires its own privacy accounting.** Every read of privacy-relevant metadata was traced: the only quantity any scaler consumes is `NoisedPytree.noise_stddev`, a public calibration constant never a function of the data; `max_norm` is dropped by `_route_noisy_pytree` and read nowhere. All state (mu, nu, v_row/v_col, v_dx, phi, z, x) is a deterministic function of already-privatised inputs — pure post-processing. `_rms_clip_transform`'s data-dependent scalar is likewise computed from post-noise values only.
- **DP-FTRL correlated-noise σ handoff:** `mf_gaussian_noise` publishes the **realized** per-step σ = base_σ·‖row_t(C⁻¹)‖ rather than the base σ, which is exactly the marginal per-coordinate variance the φ-EMA needs; because ν is a linear combination of per-step E[g̃²], only the marginals matter and the cross-step correlation does not need modelling. IdentityStrategy short-circuits to 1.0; λ-CGD uses a closed form. Non-obvious and handled right.
- **Wrapper type discipline on the update surface:** `_scale_by_*` raise when `noisy_squared_grads` and `noise_stddev` arrive together (mutually exclusive v-update branches); `make_optimizer_chain` introspects the scaler signature so Lion and SGD — which have no second moment — decline the DP metadata rather than mis-applying it; `PerGroup.for_key` raises `KeyError` on an unmapped path rather than silently defaulting to zero variance.
- **Distributed optimizer-state audit** (`optimizers/distributed.py`) correctly *refuses* to all-reduce (the state is a pure function of an already-reduced gradient) and instead fingerprints every leaf — and it deliberately fixes two weaknesses of the generic helpers: integers compared at atol=rtol=0 so adjacent step counts cannot pass under `torch.isclose`'s rtol, and tensors fingerprinted with (sum, sumsq, min, max, numel) so per-tensor drift cannot cancel arithmetically inside a single aggregate sum. (That the float32 marshalling partially defeats the first is **OPQ-049**; the design intent is right.)

### Alignment

- **`preference_collator`** (`dpo/collator/_preference.py`) is genuinely per-example on the sensitivity dimension. Truncation is keep-start at a fixed `max_length` applied identically to ids and completion masks; the only batch-dependent quantity is the padded length, and because the model is causal with right padding, pad columns cannot influence any earlier position's logits while `completion_mask` is zero there. An example's logp — and hence its gradient — is invariant to which other examples share its batch. Backed by 24 unit tests covering per-side independent padding, `pad_to_multiple_of` rounding, mask/pad alignment and determinism.
- **`language_modeling_collator`**: the batch-level `has_completion_mask` flag does **not** leak into any example's loss. The two branches for an example lacking a mask produce byte-identical `labels`; the flag only toggles whether the (unused-by-the-loss) `completion_mask` key is present. Confirmed against the SFT trainer, which reads `labels` and never `completion_mask`.
- **`sft/loss/_nll.py` and `_dft.py`**: `mask.sum(-1)` reduces over the example's own sequence axis only — no `num_items_in_batch` or any other batch aggregate anywhere in the module. `dft_loss`'s confidence weight is `.detach()`-ed so the second gradient term is genuinely suppressed. Both have real NaN-injection locality tests.
- **Fused-vs-eager label alignment:** `sequence_logp` masks with `completion_mask[..., 1:]` against `logits[..., :-1, :]`, and the fused twin's `masked_labels` encoding is equivalent because `linear_nll_sum_chunked` applies the same shift. Ignored (−100) rows contribute zero in both forward and backward. The shift convention is consistent across `sequence_logp`, `nll_loss`, `dft_loss`, `entropy_from_logits` and `mean_token_accuracy`.
- **`dpo/reference/_sync.py`**: `ema_update_reference` is a pure `optree.tree_map` returning a fresh pytree with no in-place mutation of either input, consuming only already-noised policy parameters — valid DP post-processing.
- **`dpo/data/_prompt.py`**: `extract_prompt` is a pure single-row transform — idempotent when `prompt` is present, element-wise longest-common-prefix, no state carried between rows, all other keys preserved. 16 unit tests including empty-list, no-common-prefix, unequal-length and missing-key.
- **Metric modules on the *gradient* dimension:** every returned tensor is `.detach()`-ed and the masked reductions clamp the divisor at 1, so an all-masked example yields 0 rather than NaN. The problem with these modules is disclosure (**OPQ-153**), not gradient flow.

### Trainer

- **DDP sample-rate consistency:** `_effective_train_dataset_size` trims the dataset to a multiple of world_size *before* `local_shard`, and **both** the accountant's q and the per-rank `PoissonSampler` bind to that same post-trim denominator — so expected local batch = B, cluster total = B·W, and per-record marginal inclusion is exactly q. Rank-folded sampler keys keep draws independent without changing the marginal. No accounted-q vs actual-q drift.
- **Resume rejects incomplete DP state:** `_read_runtime_for_resume` hard-requires `dp_state.pt` + `dp_optimizer.pt` + `accountant.json` and raises with an actionable message on a `save_only_model=True` weights-only export, so resume can never silently restart the accountant at zero. - **Noise-multiplier recalibration on resume is not clobbered by the restored noise state:** `GaussianNoiseState` carries only `_step_counter` and `_rng_key`; the multiplier lives in the `noise_fn` closure built from the freshly calibrated value, so restoring stream position does not revert σ.
- **Per-step budget accounting is unconditional and horizon-bounded:** `ctx.accounting |= ctx.step_process` fires before every `training_step` including empty Poisson rounds, and the loop carries a hard `if global_step >= ctx.total_steps: break` ceiling at both step and epoch level, so an epoch-driven resume with `ignore_data_skip=True` cannot overrun the calibrated composition.
- **Gradient accumulation cannot under-count amplification:** `gradient_accumulation_steps` is a read-only property pinned to 1 with no dataclass field (passing it raises TypeError), and `_batch_collapse` folds HF's `per_device × grad_accum` product into the logical Poisson batch — with an explicit comment that dropping it "would under-account the amplification and emit a too-optimistic epsilon". - **Sampling-hostile HF/TRL features are bucketed rather than silently accepted:** `group_by_length` / `length_column_name` / `train_sampling_strategy` are DROP_WITH_WARN with correct rationales; TRL's `packing` / `padding_free` / `eval_packing` / `shuffle_dataset` are REJECT_IF_SET; `fsdp` / `deepspeed` / `fp16` / `neftune_noise_alpha` / `hub_always_push` likewise raise.
- **Best-model selection cannot be driven by a training-set metric:** `__post_init__` raises when `metric_for_best_model` starts with `train_` under `load_best_model_at_end`, with an explicit memorisation-leak rationale, and `DPTrainer.evaluate` warns once when the eval dataset *is* the train dataset.
- **Checkpoint publication is crash-safe and rotation-safe:** `_save_checkpoint` writes into a `checkpoint-N.tmp` staging directory, barriers all ranks, then `os.replace`s onto the final name; the `^checkpoint-(\d+)$` discovery regex ignores `.tmp`, so a half-written checkpoint can never be selected for resume or rotation, and `rotate_checkpoints` protects both the newest and the best directory.
- **The `auto_find_microbatch_size` OOM retry is a cluster-wide collective:** `_cluster_needs_step_down` all-reduces a MAX flag so every rank steps down in lockstep, and `training_step` all-reduces a second OOM flag *between* `grad_fn` and `sum_gradients_` so no rank skips a collective. Model weights, the `requires_grad` partition, RNG state and trainer state are all snapshotted and restored before each retry. This is the one place where a data-dependent collective divergence was anticipated and correctly fixed.
- **Distributed-eval preconditions:** `get_eval_dataloader` rejects `len(eval_dataset) < world_size` and `eval_do_concat_batches=False` under DDP, with accurate reasoning about which gather issues a data-dependent number of collectives. The accumulator's own gather goes through `all_gather_object` and genuinely exchanges sizes, so ragged shards are safe **on that path** (the `gather_for_metrics` path is **OPQ-018**).
- **Constant-sensitivity enforcement under MF noise:** `mf_gaussian_noise` calls `_validate_constant_max_norm(...)`, so combining adaptive clipping with DP-FTRL raises rather than silently mis-accounting — and `TrainingArguments` rejects the same combination at config time. The docs' claim that adaptive clipping is unavailable under DP-FTRL is backed by code.
- **Cross-rank clipping-metadata consistency:** `reduce_pytree`/`sum_gradients` assert `ClippedPytree.max_norm` (and `NoisedPytree.noise_stddev`) are equal across ranks via `_assert_public_metadata_equal`, so divergent per-rank clip norms surface as a loud RuntimeError rather than a silently wrong sensitivity.

The reported `clipping_norm` is read off `grads.max_norm` (the realized threshold) rather than the configured `ctx.clip_norm` — the correct choice under adaptive clipping.

### Auditing

- **`_gdp._compute_v_k` numerical integration is correct.** Validated against the exact identity `Σ_k E[g(Y_(k))] = n·E[g(Y)]` (which holds for any g and n) at the default `grid_size=10000` across μ ∈ {0.01, 0.5, 2.0, 5.0} and n ∈ {10, 100, 500, 1500, 10000}: relative error never exceeded **3e-4**, and its sign is negative (v_k slightly under-estimated) — the conservative direction.
- **`_gdp._gdp_to_eps_delta` inversion is correct.** The bisection round-trips the closed-form `delta(eps; mu)` to within 1e-7 for μ ∈ [0.5, 5] (verified independently of the package's own test), handles μ=0 and δ≥1 explicitly, and its log-space term2 guard avoids overflow at realistic μ. Only the extreme-μ overflow path (reached solely via **OPQ-024**) misbehaves.
- **`_roc.tpr_at_given_fpr` index arithmetic is safe.** `fp_counts[0]` is provably 0 (it equals `n_out − tn_counts[-1]`), so `searchsorted(..., side='right')` always returns ≥ 1 and the `threshold − 1` access can never wrap negative. The `side='right'` choice skips past duplicate FP counts left by the Pareto filter, so the `q = (target − fp_left)/(fp_right − fp_left)` division never sees a zero denominator: 3000 randomised tie-heavy cases (2-6 distinct score values, group sizes 2-40) produced duplicate FP counts in 139 of them with **zero** non-finite results and zero exceptions.
- **`EpsDeltaMethod`'s binary-search bracket is sound**, unlike the GDP path. `_stats.search_ceiling` is the exact inverse of the u=0 perfect-attack p-value with a 1.1× pad and a floor of 1.0, and `_eps_delta._p_value` uses the same `n_eff = r − round(r·delta)` definition, so the true answer is always strictly inside `[0, eps_hi]` and the bisection cannot miss it.
- **`_roc.pareto_frontier` computes the upper convex hull correctly and enforces its own precondition.** The cross-product sign convention is the negation of the standard CCW test, so `cross_product <= 0` removes exactly the left-turn (dominated and collinear) points, iterating to a fixed point; the input-sortedness requirement is checked and raises rather than producing garbage. The problem is not the hull computation but that `attack_auc` consumes its output as if it were the raw ROC (**OPQ-059**).
- **The reference-score arithmetic in `loss_scores` matches Steinke et al. Algorithm 3.** `loss_scores` returns −loss, so `scores − reference_scores = loss(w₀) − loss(w_t)` — the paper's score and the direction the docstring claims. The shape check before subtraction raises rather than broadcasting. `gradient_scores`' sign convention likewise matches its docstring, and its refusal of `0 in batch_argnums` is correct given `torch.func.grad` differentiates argument 0.
- **The coin-flip partition is an unbiased fair coin and `split_scores` aligns correctly.** `in_mask = coin_rng.random(num_canaries) < 0.5` gives independent Bernoulli(0.5) per canary from a distinct derived key; in/out indices are exact complements under that mask; `split_scores` indexes with the same `_in_mask` that produced them; `train_indices` excludes exactly the out-canaries and retains all in-canaries plus all non-canary rows.
- **The GDP default `grid_size=10000` is adequate** for the canary counts the package targets: the v_k identity holds to 5e-4 relative error at n=10000, and ε̂ at 10000 differs from 40000 by ~1.3% in the **conservative** direction. **OPQ-060** is specifically about the permissive floor, not the default.
- **The documented `ln(m / −ln α)` canary-count table is numerically right for the method it actually describes.** The values (1000 → 5.8, 10000 → 8.1) reproduce `_stats.search_ceiling` to two significant figures, and the claim that μ-GDP is "3-10× tighter" than the (ε,δ) test is borne out (measured ratios 3.48×–5.95× across attack accuracies 58%–90%). **OPQ-063** is about the *scope* of the ceiling claim, not the arithmetic.

## 4. Refuted candidates

Sixteen findings were investigated and **dismissed**. Recorded so they are not re-raised.

1. **"Bounded Gaussian is a data-dependent renormalized truncation → ε understated"** (three separate submissions, `_gaussian.py`). **Refuted by direct computation.** The `log(Z(μ)/Z(μ'))` term is real, but it is more than offset by the tail removal that produces it — which none of the three submissions computed. Because the output is confined to [low, high], the privacy loss is a *bounded linear* function of the output rather than the Gaussian's unbounded quadratic, so the bounded mechanism satisfies pure ε-DP and its δ hits **exactly 0** at moderate ε. Worked examples: σ=1, bound=(0,10), μ=0 vs μ'=1 → δ at ε=0.5 is 0.0894/0.1465 vs the Gaussian's 0.2384; at ε=1.0, 0.00016/0.0650 vs 0.1269; total variation 0.2771 vs 0.3829. σ=1.1, bound=(−3,3), sensitivity 1 → at ε=3.0 the Gaussian has δ=4.73e-4 and the bounded mechanism has **exactly 0**. Over a 2620-point random sweep of σ, asymmetric bounds, ε and centre pairs within the clip ball, `max δ_bounded/δ_gaussian = 1.0000009` (quadrature noise). By monotonicity of f-DP composition this domination carries through the per-coordinate product and the T-step composition, so `dpsgd_acc.gaussian()` is a **valid upper bound** and the shipped examples are not publishing an invalid guarantee. One submission also used an unreachable centre pair (x=1 → x'=2 with bound=(−2,2)), since the per-coordinate centre is bounded by `clipped.max_norm = 1.0` there. *(The genuinely confirmed bounded-Gaussian issues are **OPQ-011**, float32 saturation, and **OPQ-012**, the missing derivation — see the honesty note there.)*
2. **"`likelihood_ratio_warm` indexes past its DP array and panics whenever `n_steps <= bands − 2`."** `_band_mf.py:84-86` rejects `bands > n_steps` when the strategy coefficients are materialised, and that happens inside `_pld_at_horizon` *before* the native call; combined with `rounded = min(ceil(n_steps/bands)*bands, self.n_steps) >= bands`, the argument passed to Rust always satisfies `n >= bands`. Verified by running the reporter's own scenario (ValueError, not PanicException) and a K-sweep at bands=16, n_steps=32 (no panic at any K).
3. **"DP bias correction has no lower bound on the corrected second moment; `bc_floor` is never applied, producing unbounded updates."** `_adam.py:241/254` place eps **outside** the sqrt (`v_hat.sqrt() + eps`), so the update is bounded by |m̂|/eps. `bc_floor = eps*eps` and `sqrt(eps²) == eps`, so applying the documented floor would change the worst-case denominator from eps to 2·eps — a factor of 2, which cannot account for the claimed 2243-vs-1.28 gap. On the `corrected <= 0` branch the shipped `torch.where(corrected > 0, corrected, v_raw)` fallback yields a *strictly larger* denominator than the documented floor would. `noise_bias_correction` also defaults to False, and the docs already state BC-on requires a tuned LR.
4. **"The per-sample LoRA *weight*-gradient vmap rules — the actual DP-SGD path — are not covered by any numerical test."** `tests/peft/test_fused_lora_mlp.py:77-164` executes `_LoRAMLPBackward.vmap` with weight grads enabled and compares every per-sample dA/dB against a per-example autograd loop at rel < 1e-2. It is not gated behind `@requires_hf_auth` (it builds a Qwen2Config locally) and was written specifically as a regression test for the X-storage-reuse ordering the finding claims is untested.
5. **"Declared DP-regression gate (50-step ε=10 loss snapshots) and DPO reward-metric parity gate do not exist."** `docs/development/trl-trainers-plan.md:3` declares "Status: Planning"; §15 is "Phase 5" of a phased plan with an unstarted work-unit DAG and an "Effort: M (3–4 days)" estimate; `mkdocs.yml` has no "development" nav entry, so the file is not published. A planning document listing gates it intends to build is not a claim that those gates protect main. *(The related, real finding is **OPQ-072**.)*
6. **"`_assert_public_metadata_equal` compares PerGroup max_norms in dict-iteration order after only checking the key set."** `_per_group.py:129-134` builds `values` from `all_patterns.items()` in deterministic insertion order (the `set` is only a membership filter), and `dpsgd/clipping/_distributed.py:59` rebuilds per-group values in `sorted()` order — so all ranks running the same SPMD script hold identically ordered dicts. The collective count is also order-independent (`2 * len(values)` on every rank) and `gradients.py:58` asserts the key set first. No hang, no silent divergence.
7. **"The only end-to-end DP-SGD/DP-FTRL pipeline tests that run on CPU assert nothing beyond finiteness and shape."** pr.yml:96-113 + :153 run `packages/opaque-transformers` on the **blocking** CPU leg, and `tests/validation/test_dp_guarantees.py` has no module-level marks, forces `use_cpu=True`, and asserts calibrated-σ-vs-reference-accountant, exact composition count, seed sensitivity at σ>0, per-example clip bounds, and realised noise stddev == nm·C.
8. **"No detection of a stale or un-threaded `GaussianNoiseState`: reusing the same state reproduces identical noise."** `tests/noise/test_noise.py:256` **asserts** that feeding the same state twice yields identical noise, and `dpsgd/noise/_distributed.py:21` (`"_step_counter": "assert_equal"`) *requires* all ranks to draw from the same counter value. Both make the proposed "raise on a repeated step_counter" guard incorrect, not merely costly. At most this justifies a one-line caution in `docs/user-guide/dp-sgd.md`.
9. **"A `NoisedPytree` with `noise_stddev=None` silently disables BC while the φ-EMA decays, under-subtracting."** `_adam.py:139-142` initialises `phi=0.0`; `update_phi_ema` returns `b2*0.0 + (1−b2)*0.0 = 0.0`, so φ never becomes non-zero when σ is always None — there is nothing to "decay" and nothing to under-subtract. `_adam.py:249-258` then routes to the plain vanilla-Adam formula, which is exactly the documented "Neither" branch. The mixed-σ scenario required for the described contamination is unreachable: `_gaussian.py:354-361/402-406`, `_mf_gaussian_noise.py:187` and `_second_moment.py:166-172` all set `noise_stddev` unconditionally, and `noised()` makes it a required argument.
10. **"HF's `schedule_free_adamw`/`schedule_free_sgd` are rejected while `schedule_free_radam` is aliased."** `tests/validation/test_dp_trainer_optimizer_aliases.py:100-102` explicitly asserts these two names are rejected, with a comment stating the redirect to `optim='schedule_free'` is intentional. Implementing the proposed fix would make that test fail.
11. **"`dataloader_drop_last` is accepted and documented but silently inert on the training path."** `docs/user-guide/distributed-trainer.md:68` documents the field verbatim as "(eval loader only)" and `docs/user-guide/huggingface/training-arguments.md:298` explains why it is inapplicable to the DP training path. The behaviour is additionally forced by PyTorch: `_dp_trainer.py:3406` passes `batch_sampler=sampler`, and `DataLoader` raises if `drop_last` is combined with `batch_sampler`. Documented deliberate choice, not an unimplemented field.
12. **"`CoinFlip` does not record the dataset size, so `train_indices(dataset_size)` silently returns a wrong training set on a mismatch."** `_coin_flip.py:67-68` filters `range(dataset_size)` and removes out_indices — a set subtraction that can only *shrink* the index set, so no out-canary can re-enter training on a second application; the claimed ε-affecting mechanism does not exist. Reachability is further undercut by all three examples applying the filter once and storing `audit_dataset` before filtering, and by the tutorial's `cf.train_subset(dataset)`, which computes `len()` internally.
13. **"'Pillutla Score' is not a construct in the cited paper and the stated guarantee is not what Theorem 1 says."** `_blt_math.py:343-356` shows the inverse's decay parameters are the eigenvalues of `diag(buf_decay) − outer(output_scale, ones)`, whose characteristic equation is `1 + Σ w_i/(μ − λ_i) = 0`; evaluating at μ=0 gives `1 − pillutla_score()`, so `score < 1` is **exactly** the condition for all inverse decay parameters to be positive — the docstring's "well-behaved inverse" claim, verbatim. And because `buf_decay ∈ (0,1)` makes `Σ w_i/λ_i > Σ w_i`, `score < 1` already implies `Σ α_i < 1`, so the claimed "admits a BLT Theorem 1 excludes" case is arithmetically impossible. The docstring says "well-behaved", never "invertible", and the real gate is the decay-gap check at `:335-341`.
14. **"Rust adaclip doc calls the returned quantity 'the combined L2 sensitivity' when it is the reciprocal of the effective noise multiplier."** `adaclip.rs:11-18, 24` label it "the combined L2 sensitivity z-tilde" and never call it a noise multiplier, and the value genuinely *is* the L2 sensitivity of the concatenated (gradient sum, K quantile) query after normalising each component's noise std to 1 — the standard Andrew et al. framing. The claimed "backwards monotonicity" is correct behaviour for a sensitivity. `opaque_accounting.pyi:869` already carries the "Andrew et al. 2021" citation the fix sketch asked to add.

### Accounting — DP-FTRL strategies

**OPQ-177 — `BandMfStrategy.sensitivity()` returns 1.0 for every participation context, so `MfGaussian.pld` prices a multi-participation BandMF run as if each record participated once.** `packages/opaque-dpftrl/src/opaque/api/dpftrl/noise/_band_mf.py:137-139`; `_toeplitz.py:570`; consumed at `packages/opaque-dpftrl/src/opaque/api/accounting/dpftrl/mechanisms/_mf_gaussian.py:77-86` · privacy-correctness · ε:yes · **CONFIRMED**. `sensitivity(self, *, n_steps, **_)` returns `float(coefs.norm())`, and `_toeplitz.py:570` ends the optimiser with `params / torch.linalg.norm(params)` — so the norm is 1.0 by construction and `min_sep` / `max_participations` are swallowed by `**_`. Measured: `band_mf_strategy(bands=2)` and `bands=8` both return **1.000000** at `(min_sep=32, E=4)` *and* at `(min_sep=8, E=16)`; `bsr_strategy(bandwidth=2, α=0.7, β=0.3)` over the same contexts returns **2.236068 → 4.472136**, the √E scaling BandMF is missing. Since sensitivity enters as σ_eff = σ/sens, this under-reports ε. **Fix:** a contract decision, not a one-liner — `_poisson.py:160` and `_b_min_sep/__init__.py:146` want the single-participation value, four shipped tests assert `== 1.0`, and `types.py:39` documents the drop as intended. Recommended: keep `sensitivity()` single-participation and make `MfGaussian.pld` either compute the multi-participation value itself or refuse a BandMF strategy with `max_participations > 1`. **Notes:** partially undermines the premise of the existing "Paired second-moment MF allocation splits the budget with single-participation sensitivities" finding, which assumes `sensitivity(n_steps, min_sep, max_participations)` is participation-dependent — for BandMF it is not.

**OPQ-178 — BLT builds its balls-in-bins Gram from the column-normalised encoder while deploying the raw one, under-reporting ε by ~1.6×.** `packages/opaque-dpftrl/src/opaque/api/dpftrl/noise/_blt.py:111`; repeated at `.../accounting/dpftrl/amplification/_balls_in_bins.py:193-199` · privacy-correctness · ε:yes · **CONFIRMED**. `_blt_gram_matrix` passes `normalized=True`, and the pinned K-prefix path passes `True` again, but `BltStrategy.streaming_matrix` (`_blt.py:168-174`) and `.sensitivity` (`:176-192`) both use raw coefficients — so the accountant prices a different matrix from the one deployed. `bnb_mc_pld` applies no compensating rescale (`monte_carlo.rs:170-176`), and shrinking G by s² is equivalent to inflating σ by 1/s. `BsrStrategy` passes `False` in the same position (`_bsr.py:117-119`), so BLT is the outlier. Decisive control: with `C = α·I` the normalised Gram is `E·I` *independent of α*, so `bnb_mc_pld` returns **ε = 4.24584 for α ∈ {0.5, 1, 2}** while the true mechanism gives **1.21093 / 4.24584 / 12.75634**. On a real strategy (b=16, E=4): Gram diagonal 5.01128 vs 11.34671 raw; ε at δ=1e-5 is **3.96993 shipped vs 6.31958 correct (1.592×)**, and 1.40537 vs 2.19030 at σ=5 (1.559×). **Fix:** pass `False` in both places — normalising the deployment instead would change the released mechanism. Land with the α-scaling regression test. No golden BLT BnB ε values are pinned anywhere (`test_per_step_invariants.py:301` asserts only monotonicity in K and boundedness), so there is no expected-value churn.

**OPQ-179 — `toeplitz_gram_matrix` forms signed column inner products where Lemma 3.2 requires `|C|`, and no BandMF/BLT path validates the coefficients non-negative.** `packages/opaque-accounting/src/matrix_factorization/bisr.rs:583-593`; `packages/opaque-dpftrl/src/opaque/api/dpftrl/noise/_toeplitz.py:565-569` · privacy-correctness · ε:yes (latent) · **PLAUSIBLE**. The Lemma 3.2 mixture mean is `m_i = Σ_j |C|[:, b·j+i]`; the Gram builder uses signed products. These agree only when the coefficients are non-negative. BSR constrains them (`_bsr.py:98-102`); BandMF runs L-BFGS-B unbounded; BLT bypasses the sign check with `skip_checks=True` (`_blt.py:187-193`). A negative coefficient shrinks the signed Gram relative to the `|C|` Gram — the unsafe direction. **Not established:** whether any reachable configuration produces one. A survey sweep over bands ∈ {2..64} × eight momentum values found none, but was not exhaustive and no positivity proof exists. **Fix:** take `|coefs|` before forming the Gram (correct by Lemma 3.2, cannot fail closed), or assert non-negativity — but do **not** add the assert before confirming BLT's coefficients are non-negative, or it will hard-fail BLT at runtime.

### Accounting — Rust numerics and metrics

**OPQ-180 — `MixtureConstants::min_positive_sensitivity` returns a hardcoded `1.0`, ignoring `self.sensitivities`, and feeds the δ bisection bracket.** `packages/opaque-accounting/src/amplification/parallel_poisson.rs:168-170`, consumer at `:226`, expansion loop at `:249-261` · numerical-correctness · ε:yes (latent) · **CONFIRMED**. The function body is literally `1.0`. The current caller is immune by accident: `from_log_probs` produces binomial sensitivities whose minimum positive value *is* exactly 1. Two sibling assumptions in the same constructor: `sampling_prob = 1.0 − log_probs[0].exp()` (`:151`) assumes index 0 carries the zero sensitivity, and `max_sensitivity()` (`:164-166`) assumes sortedness. **Fix:** compute the minimum over positive entries, locate the zero-sensitivity index rather than assuming it, and take an actual max — all three together, and **with** the generalisation that needs them (the postponed mixture-Gaussian primitive for SK26), not before. **Notes:** the expansion loop at `:249-261` would mask a bad bracket in easy cases, which makes this worse rather than better — quiet under-reporting of δ instead of a loud failure.

**OPQ-181 — `pmf_beta_asymmetric` discards `negative_infinity_mass` while the symmetric path keeps it, so `beta_at()` and `delta_at()` disagree on every asymmetric PLD.** `packages/opaque-accounting/src/pld/metrics.rs:297-306` vs `:204-211` · privacy-correctness · ε:no · **PLAUSIBLE**. The symmetric path seeds `cdf_y[0] = pmf.negative_infinity_mass + pmf.probs[0]` and its own comment calls that conservative; the asymmetric path states "No `negative_infinity_mass`: it's absorbed by the renormalization". Every amplification primitive returns `new_asymmetric`, and both `disc_dist(Rounding::Down)` and `GeomPmf::into_pmf_log` actively *produce* −∞ mass — so the conservative treatment is applied on the paths that do not generate such mass and skipped on the paths that do. **Not measured:** the size of the resulting discrepancy. **Fix:** decide which treatment is correct, apply it to both, and add a test that `beta_at` and `delta_at` agree through the (ε,δ) ↔ (α,β) correspondence on an amplified PLD. Measure the magnitude first — it may be negligible, which changes the priority.

**OPQ-182 — Balls-in-bins Monte Carlo ε depends on `RAYON_NUM_THREADS` at fixed seed (~11.9% spread).** `packages/opaque-accounting/src/amplification/balls_in_bins/monte_carlo.rs:188`, `:201`, `:231` · numerical-correctness · ε:yes · **PLAUSIBLE**. The driver shards by `rayon::current_num_threads()` and seeds shards as `seed + tid`, so the realised sample set is a function of the host core count even with the user's seed fixed. Survey measurement at seed=42, (b=16, E=4, σ=1.0, n=1e5): **9.063 at 4 threads vs 8.102 at 1 thread**. This is the property the deterministic transform removed for the identity path; the correlated-strategy path still has it. **Fix:** shard by a fixed count derived from `num_mc_samples` alone and seed by shard index — the same fix already applied to `GeomPmf::conv` (`ROW_CHUNKS`) — then extend `tests/test_random_allocation_reproducible.py` to cover `bnb_mc_pld`. **Notes:** this makes MC *reproducible*, not *sound*; it does not touch the confidence-correction defect in the same file.

**OPQ-183 — `GeomPmf::conv` clamps negative bin indices to bin 0 in both rounding directions, rounding up under `Rounding::Down`.** `packages/opaque-accounting/src/pld/pmf/geom.rs:197` vs `:140-147` · numerical-correctness · ε:no (today) · **CONFIRMED**. The scalar `place` helper branches on direction (`Up → probs[0]`, `Down → zero_mass`); the parallel interior core does not — `acc[(idx.max(0.0)) as usize] += mass` sends negatives to bin 0 regardless, which under `Rounding::Down` moves mass *up* and breaks the domination direction the lower bound relies on. Unreachable on the current index expression, but a survey agent observed `K_down[0] = −1` while prototyping the Toeplitz index-table optimisation, which would make it live. **Fix:** mirror the scalar path — route negatives to a per-chunk `zero_mass` accumulator under `Down`. Do this **before or with** the index-table change, never after.

### Evidence added to an existing finding

The survey independently re-confirmed **"Monte-Carlo PLDs are point estimates with no confidence correction"** and sharpened it: the consequence is a hard **cap**, not a convergence rate. With `G = E·I` (b=16, E=4, σ=1) `bnb_mc_pld` ε is flat at **9.064 for δ = 1e-8, 1e-11 and 1e-14**, while the exact identity path gives **9.98242 → 12.20753 → 14.12360**. No sample budget closes that gap, because `infinity_mass` is identically 0. At production δ=1e-8 the under-report is 9.2%. That evidence was merged into the existing entry in `auditraw.json` rather than opening a duplicate id. **One staleness note:** that entry cites `identity.rs:129-224 (weighted_samples_to_pmf)`, which no longer exists — it was deleted when the identity balls-in-bins path moved to the deterministic transform. `monte_carlo.rs` and `b_min_sep/mc.rs` remain affected.
