### The five that matter most

1. **OPQ-318 — `mf_band` + `sampling_mode="poisson"` is a blessed, validated, test-pinned pairing
   of the cyclic-Poisson accountant with a plain full-dataset Poisson sampler.** The accountant
   charges `ceil(n/bands)` per-group Poisson-Gaussian compositions at sensitivity 1.0 — the
   Choquette-Choo et al. (2023) Theorem 4 reduction, which requires Algorithm 2's cyclic
   partition. The deployed sampler makes every record eligible on every round. Measured
   under-charge: reported ε=0.355 where recomputing only the realistic per-band-window inclusion
   probability already gives 3.505 (≈10×). Documented as a supported alternative; the sampler that
   *does* match (`CyclicPoissonSampler`) is implemented and reachable in code but excluded from the
   allow-list. This is the single largest ε-affecting defect in the delta, and the fix is a
   one-line allow-list change.
2. **OPQ-319 — calibrated DP-FTRL resume silently changes σ mid-horizon, and the guard written for
   exactly this case is bypassed for calibrated runs.** `noise_multiplier` is tagged
   `drift="dp_relevant"` and DP-FTRL raises on such drift — but `_current_values_for_drift` returns
   `None` for it when `calibration_source == "calibrated"`, i.e. the one resume mode that always
   moves σ. The rebuilt `mf_gaussian_noise` closes over the new σ while the restored streaming
   buffer holds old-σ-scaled columns, so the next `bands-1` releases are a σ-heterogeneous mixture
   no accountant models. Measured: a mid-band resume raises the multiplier 2.5–3.6 % (and 9.1 % if
   the target is changed, which is never checked at all), leaving those steps under-noised relative
   to what the suffix accounting charges. No exception, no warning.
3. **OPQ-314 — λ-CGD is the one surviving unrooted privacy-noise stream after the breaking #728
   namespacing fix.** `fold_in(key, step)` on the caller's own key space: verified that step-*t*
   noise is byte-identical to `torch.randn(generator=generator_from_key(split(user_key)[t]))`. Any
   caller who derives sibling keys from the base they handed the mechanism — the pattern
   `docs/reference/rng.md` teaches — can reproduce the injected DP noise exactly. The guard test
   `test_stream_root_namespacing.py` structurally cannot see it (it enumerates declared root
   constants; λ-CGD declares none), and rng.md publishes a tag table asserting the stream *is*
   rooted.
4. **OPQ-354 — the documented "Unamplified BLT/BandMF" accounting recipe silently prices a one-step,
   single-participation mechanism**, because `MfGaussian` defaults `n_steps=1` / `min_sep=1` /
   `max_participations=None`. Measured 4.377 where the same page's own multi-epoch example context
   gives 28.159 (6.4×) and its 10 000-step example gives ∞. The snippet ships with an
   `assert eps > 0 and eps < inf` that makes the wrong number look validated, and is repeated
   verbatim in three user-facing pages. Nothing in CI executes docs snippets.
5. **OPQ-337 — the sliding-window constraint is silently dropped under SDPA whenever
   `attention_mask is None`.** `vmap_create_causal_mask` returns `None` (the `is_causal` fast path)
   with no sliding-window awareness and the sliding-window builder forwards that `None`, so patched
   Mistral/Gemma2/Gemma3/Cohere2/Phi-3 attend to the full context on sliding layers. Upstream
   explicitly refuses this skip (`masking_utils.py:262-263`). Reproduced: patched logits deviate
   0.158 max-abs from upstream on a window-binding input with no mask, and match bit-for-bit with
   one. Every existing sliding-window test uses `eager`, so the SDPA branch is untested.

Honourable mentions, both ε-affecting and both cheap: **OPQ-300** (the b-min-sep warm-start
likelihood ratio is not the likelihood ratio of any initial-state mixture — the add-direction PLD

**OPQ-300 — b-min-sep warm-start likelihood ratio misnormalizes the stationary mixture; the add-direction PLD is anti-conservative.** `packages/opaque-accounting/src/amplification/b_min_sep/mc.rs:69-75` · privacy-correctness · **medium** · ε:yes · **CONFIRMED**.
- **Claim:** `likelihood_ratio_warm` computes `sum_f = f[0] + p*tail/denom` with `denom = 1+(b-1)p`, dividing only the barred-start terms. The module's own sampler `sample_x_under_p` (`:85-108`) draws the initial barred state from the stationary law (state 0 w.p. `1/denom`, state j w.p. `p/denom`), whose exact density ratio is `(f[0] + p*sum_j f[j])/denom`. The shipped expression is therefore not the likelihood ratio of *any* initial-state mixture (`E_Q[r] = 1 + (b-1)p/denom > 1`), so the samples fed to the #748 confidence-band machinery are `ln` of an inflated statistic: the remove PLD is inflated (conservative but loose) and the add PLD is shifted **down** (invalid).
- **Failure scenario:** any BandMF + b-min-sep run — the default sampler for `mf_band`. Verified against exact enumeration of all warm-start participation patterns (b=2,3; n=8..10): the corrected formula matches to ~1e-15, the shipped one overstates by 1.048–1.171×. Because `epsilon_at` takes the max over adjacencies and the inflated remove side bound in every configuration tested, the user-visible effect today is an **over**-stated ε (1.271 vs 1.224 at the repo's own smoke config; 1.390 vs 1.178 at 16 bands, p=0.02, δ=1e-2) — silent over-noising and lost utility. The mirror-image deflation of the add side (0.381 vs a true 0.585) makes that component an invalid bound that would understate ε in any composition where the add adjacency binds.
- **Evidence:** `mc.rs:69-75` (f[0] undivided) vs `mc.rs:87-96` (stationary draw); independent exact enumeration (`scratchpad/vfy_lr.py`) and MC quantification (`scratchpad/vfy_lr_eps.py`, 100–200k samples); `PrivacyLossDistribution::epsilon_at` maxes over adjacencies (`pld/mod.rs:266-293`); no test compares bands≥2 output to any oracle; bug predates the audit (5de05eb0, #121) and survived PR #748, which rewrote the surrounding sample-to-PMF pipeline without touching these four lines.
- **Fix:** `sum_f = (f[0] + p * tail) / denom` (tail 0 when `bands == 1`). Add a normalization test asserting empirical `E_Q[likelihood_ratio_warm] ≈ 1` for bands ∈ {2,4,8}, and a bands=1 oracle test asserting the MC bound dominates `poisson_gaussian_pld(sigma,p).self_compose(n)`.

**OPQ-301 — b-min-sep Monte Carlo transcripts are sharded by the live Rayon thread count: a fixed seed yields a different ε on a different host.** `packages/opaque-accounting/src/amplification/b_min_sep/mc.rs:174-176, 187, 210, 364-378, 404` · reproducibility · **medium** · ε:yes · **CONFIRMED**. *(merges three independently reported instances: "b-min-sep MC transcripts are sharded by live Rayon thread count", "b-min-sep MC still thread-count nondeterministic (pattern #331 fixed for balls-in-bins)", "b-min-sep Monte Carlo epsilon depends on Rayon thread count with a fixed seed".)*
- **Claim:** the fix for closed #331 converted the balls-in-bins driver to fixed 1024-sample, shard-index-seeded chunks (`balls_in_bins/monte_carlo.rs:43-55`, with an explicit comment that shard count must not depend on the worker count, a Rust identity test at `:549`, and a Python subprocess test). The sibling b-min-sep driver — rewritten by the same PR #748 for the confidence-band plumbing — still does `n_threads = rayon::current_num_threads().max(1)` and seeds per-thread RNGs `seed+tid` (remove) / `seed+1000+tid` (add), in **both** `bandmf_b_min_sep_warm_mc_pld` and `bandmf_b_min_sep_prepare_transcripts`, so the cached transcript corpus bakes in the host's core count. The Python transcript cache key does not include the thread count. `seed+1000+tid` also collides with the remove streams above 1000 workers (theoretical).
- **Failure scenario:** a team pins a seed for a BandMF + b-min-sep run and gets a different reported ε on different hardware. Measured through the built extension at seed 173 (coef `[√0.7, √0.3]`, n=50, p=0.05, σ=1.0, mc_resolution 5e-3): `epsilon_at(1e-2)` = 1.5789 (1 worker) / 1.5938 (2) / 1.8443 (8) — a 17 % swing. Calibration on a many-core box selects a different noise multiplier than the same config in CI, and a published (ε, δ, seed) triple is not reproducible by a third party. Each individual value remains a valid confidence bound, so this is nondeterminism of the reported guarantee, not an unsound one.
- **Evidence:** the three `current_num_threads()` sites are the only ones in the crate; `reproducibility` is a documented contract of `seed` (`opaque_accounting.pyi:166`, `discretization.py:25/123`); the only regression test (`tests/test_balls_in_bins_reproducible.py`) covers balls-in-bins alone; `git show 88a25769` shows #748 editing around the thread partition without porting the shard scheme; reachable publicly via `opaque.dpftrl.accounting.b_min_sep`.
- **Fix:** port the balls-in-bins scheme — `par_chunks_mut(SAMPLES_PER_SHARD)` with `shard_seed(seed, shard, direction)` independent of the pool size, for both entry points; derive transcript layout from the shard index; extend the reproducibility subprocess test to `bandmf_b_min_sep_warm_mc_pld`; version-tag or regenerate cached corpora. Use a domain-separated direction offset instead of `+1000`.

**OPQ-302 — `from_state_dict(Accountant(budget=...), sd)` silently discards the template's budget; `budget_exceeded` then fails open forever.** `packages/opaque-accounting/src/opaque/api/accounting/core/_accountant.py:222-247, 205-221` · api-misuse/fail-open · **medium** · ε:yes · **CONFIRMED**.
- **Claim:** the serializer is registered as `lambda _template, sd: _accountant_from_state_dict(dict(sd))` — the template is never read. `_accountant_state_dict` emits a `budget` key only when `acct._budget is not None`, and the loader sets `budget = None` when the key is absent, so restoring a budget-less checkpoint into a budgeted template yields `_budget = None`. `budget_exceeded` then hits `if self._budget is None: return False` unconditionally. This contradicts the dispatcher's own documented contract (`_dispatch.py:96-106`, "missing leaves keep the template's value").
- **Failure scenario:** stage 1 trains with a fixed multiplier and no budget (what DPTrainer always writes — `_dp_trainer.py:1536` constructs `Accountant()`), stage 2 resumes with the natural one-liner `acct = from_state_dict(Accountant(budget=epsilon_budget(1.0, delta=1e-5)), json.load(f))` and drives the documented `acct = acct | step; if acct.budget_exceeded: break` loop. Reproduced: after the restored 2000-step prefix, `epsilon_at(1e-5) = 2.1597`, `_budget = None`, `budget_exceeded = False` — the loop never breaks, the run continues past 2.16× its stated cap, with no error, warning or log line. The documented recipe (restore bare, then rebuild `Accountant(budget=..., prefix=restored.process)`) sidesteps it; the failing form is the one the dispatcher contract invites.
- **Evidence:** `_accountant.py:243-247` (template ignored), `:231-235` (budget defaults to None), `:215-216` (fail-open branch); control run confirms the key round-trips when the saved accountant *had* a budget; no public way to detect the loss short of reading `_budget`.
- **Fix:** have the loader keep `template._budget` when the saved dict has no `budget` key; make `budget_exceeded` distinguish "no budget configured" from "budget could not be restored" (raise or tri-state) and log at restore time whenever a template budget is discarded.

**OPQ-303 — self-convolution exponent silently truncated to `u32` on the budgeted circular path.** `packages/opaque-accounting/src/numerics/fft.rs:316-318` · numerical-correctness · **low** · ε:yes · **CONFIRMED**.
- **Claim:** after the #341/#528 fixes one overflow survives: `*c = c.powu(count as u32)` wraps `count` modulo 2³². For a multi-element PMF the linear strategy is rejected at that size, but with a tail budget set the circular fallback is taken and the spectrum is raised to the wrapped power — composing `count mod 2³²` steps instead of `count`.
- **Failure scenario:** reproduced with a temporary Rust integration test: `self_convolve_with_bounds(&[0.5,0.5], (1<<32)+10, Some((0,15)), true)` returns `Ok` with values bit-identical to the 10-fold result — an ε under-report by orders of magnitude, no error. The documented Python surface is safe (`python/pld.rs:31-39` caps at `u32::MAX` with `OverflowError`); the wrap is reachable from the crate's rlib API (`self_convolve_with_bounds` / `Pmf::self_compose` are `pub`), and in principle via `random_allocation_gaussian_pld`'s unbounded `k`, which needs `k > 4.29e9` — not a realistic input.
- **Evidence:** `fft.rs:316-318` (`Complex::powu` takes `u32`); `fft.rs:187-193` checks only `usize` overflow of the result length; the strategy selector merely routes an oversized request to the circular branch when a budget permits.
- **Fix:** guard in `self_convolve_with_bounds` (`if count > u32::MAX as usize { return Err(...) }`, mirroring the Python boundary), or use repeated squaring of the spectrum with a `usize` exponent as `pow_usize` already does for the singleton case.

**OPQ-304 — `set_discretization` is a full replace, not a partial update: tuning one knob reverts every previously tightened Monte Carlo / grid parameter.** `packages/opaque-accounting/src/opaque/api/accounting/core/discretization.py:97-154` · api-misuse/stateful-setter · **low** · ε:yes · **CONFIRMED**.
- **Claim:** the setter assigns `_default_config = DiscretizationConfig(<all eight params>)` without reading the existing config, so any omitted parameter resets to the library default. Its own docstring example — `acc.set_discretization(discretization=1e-3)` — is exactly the single-knob shape that silently undoes prior settings, and the sibling `get_discretization` is keyword-only with `None` sentinels, i.e. genuinely an override.
- **Failure scenario:** reproduced in one process: `set_discretization(mc_failure_probability=1e-10, mc_resolution=1e-8)` → 1e-08/1e-10; then `set_discretization(discretization=1e-3)` → `discretization=0.001, mc_resolution=1e-05, mc_failure_probability=1e-06`. Both Monte Carlo band parameters are silently back at defaults, four orders of magnitude looser on the failure probability, and every ε computed afterwards by the MC accountants (b-min-sep, balls-in-bins — the auto samplers for 5 of 6 MF mechanisms) is certified at a weaker confidence level than configured.
- **Evidence:** `discretization.py:145-154` constructs from arguments alone; `:132-133` is the misleading docstring example; `get_discretization` (`:147-166`) has the opposite semantics.
- **Fix:** give every parameter a `None` sentinel and merge onto the current `_default_config` (matching `get_discretization`), or rename to `replace_discretization` and add an explicit `update_discretization`. Make the parameters keyword-only for symmetry.

**OPQ-305 — closed #338 landed no change: asymmetric PLD β metrics still renormalize `negative_infinity_mass` away, inconsistently with the symmetric path.** `packages/opaque-accounting/src/pld/metrics.rs:305-314` · correctness · **low** · ε:no · **PLAUSIBLE**.
- **Claim:** the symmetric `pmf_beta` folds `negative_infinity_mass` into `cdf_y[0]` with the comment "keeping beta estimates conservative" (`:211-216`); `pmf_beta_asymmetric` instead runs both PMFs through `clean_probs`, which rescales the finite mass to `1 - infinity_mass` and drops the negative-infinity mass (`:305`, `:314`, "matching riskcal"). `git log` over the delta for this file returns only #466 and #283, neither touching the constant — the reconciliation the closed issue's title names never landed.

**OPQ-306 — `random_allocation.rs` module docstring claims the discretisation error does not accumulate across the exponentiation-by-squaring convolutions; the over-estimate grows with `t`.** `packages/opaque-accounting/src/amplification/random_allocation.rs:13-15` · misleading-docs · **low** · ε:no · **CONFIRMED**.
- **Claim:** "Crucially the discretisation error does **not** accumulate across them, which is what makes large `t` tractable." What does not accumulate is the *grid size* (`conv` re-anchors and keeps `n` fixed, `geom.rs:196-208`); the error does accumulate, because `conv` rounds every off-grid sum **up** to the next geometric grid point (`geom.rs:180-186, 267-280`), once per squaring and per multiply.
- **Failure scenario:** a reader sizing `max_conv_grid` for a large-`t` run concludes the bound is grid-insensitive and leaves the default. Verified by varying only `max_conv_grid`: ε at σ=1.0, δ=1e-5 for one full epoch, coarse (1024) minus fine (4096), is +0.0159 at t=2 rising to +0.0743 at t=256 — 0.43 % relative rising to 21 %. The rounding is directional and conservative, so ε is over-stated, never under-stated.
- **Evidence:** the docstring; `geom.rs` rounding sites; the crate's own `test_larger_max_conv_grid_tightens_bound` (`random_allocation.rs:780-801`) already encodes the grid dependence.
- **Fix:** reword to "the grid size does not grow across them" and state the actual error budget (bounded by roughly `(floor(log2 t) + popcount(t) - 1) · alpha` in absolute loss) so users can size `max_conv_grid` against an accuracy target.

### 2.2 DP-SGD (`opaque-dpsgd`)

**OPQ-309 — per-group adaptive clip sync reduces group counts positionally, so an empty rank receives permuted counts and thresholds diverge.** `packages/opaque-dpsgd/src/opaque/api/dpsgd/clipping/_distributed.py:64-66` · distributed-privacy-correctness · **medium** · ε:no · **CONFIRMED**.

- **Evidence:** the positional reduce loop; the three divergent construction sites; the in-process demo of key-order flip; the 2-rank gloo repro; existing DDP tests (`tests/ddp/dpsgd_ddp_helpers.py:358-470`) use identical literal dict order or `return_aux=True` on all ranks, so the case is untested. Add a 2-rank gloo test with one empty rank and a non-sorted, non-leaf PerGroup order.

### Monte-Carlo confidence machinery

- The concentration inequality was re-derived: for any F (atoms included),
  `P[F(X_(rank)) < p] ≤ P[Bin(n,p) ≥ rank] ≤ exp(-n·KL(rank/n‖p))`. `kl_lower_cdf_bound` bisects the
  monotone-decreasing KL on `[0, rank/n]` and keeps the conservative side; `binary_kl` handles q≥1 as
  `-ln p` correctly.
- The band is applied to the right functional and one-sided in the safe direction for balls-in-bins:
  Lemma 3.2 was re-derived after Gram reduction and both directions match `monte_carlo.rs:61-134`
  exactly; `samples_to_pmf` shifts mass only upward.
- `resolved_num_mc_samples` algebra verified (final-rank residual `1-(failure/(2n))^{1/n}` equals
  `-(per_rank.ln()/n).exp_m1()`; binary search returns the minimal n); `samples_to_pmf` fails closed
  when achieved `infinity_mass` exceeds the requested `mc_resolution` or total mass deviates by >1e-9;
  non-finite samples hard-error.
- Union-bound bookkeeping: per-rank failure = `failure/(num_directions·n)` with `num_directions=2`
  passed by both entry points, covering all n ranks in both adjacency directions; monotone CDF enforced.
- Numerical oracles: identity-Gram BnB MC bound ≥ exact `random_allocation_gaussian_pld` at δ ∈
  6e-3..5e-2 (1.477 vs 1.109 at δ=1e-2); bands=1 b-min-sep MC bound ≥ analytic
  `poisson_gaussian_pld(σ,p).self_compose(n)` at three δ; `epsilon_at(δ ≤ infinity_mass)` returns ∞.
- Non-certified metrics fail closed: `beta_at` and `risk_at` return 0.0 for any PLD with
  `estimation_failure_probability > 0` — the attacker-perfect, privacy-safe direction — and
  `advantage() = delta_at(0)` includes `infinity_mass`, so it is certified.
- Confidence-metadata algebra under composition: `compose()` adds failure probabilities (union bound,
  capped) and combines resolutions as `1-(1-a)(1-b)`; `self_compose()` keeps failure fixed, which is
  statistically sound because on the confidence event the estimated single-step loss stochastically
  dominates. `Composed` splits failure evenly and resolution as `1-(1-r)^{1/groups}` with recursive
  re-splitting; `Repeated` correctly does **not** split failure.
- The confidence parameters reach the user-facing API (constructor args, per-query overrides on every
  `DpProcess` metric method and on `pld_at`, readable back off the `Pld`).
- **Balls-in-bins thread-count and seed reproducibility (the #331 fix) is genuinely fixed**: fixed
  1024-sample shards with shard-index-only seeds and disjoint even/odd direction offsets,
  `par_chunks_mut` partition independent of the pool, `par_sort` making bucket construction
  order-invariant — verified by the in-tree Rust identity test and the Python subprocess test. (The
  *sibling* b-min-sep driver is OPQ-301.)
- The identity-strategy BnB path bypasses Monte Carlo entirely (deterministic random-allocation
  transform) with the exact `G = E·I` collapse re-derived; transcript-reuse prefix slicing is a valid
  projection because `sample_x_under_p` is causal, and the Python cache key includes resolved sample
  count and seed.
